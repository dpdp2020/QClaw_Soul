# TEAM-RULES.md — Agent 团队统一日志规范

> 本规范适用于所有 Agent（牛牛、学习官、新闻官、策略官、交易官、麦导、节哥、花花等）。
> 每个 Agent 必须在 SOUL.md 或 AGENTS.md 中引用本规范，确保执行。

---

## 📋 日志规范

### 1. 位置

所有任务日志统一放在各 Agent workspace 的 `memory/` 目录下。

```
D:\wujm\QClaw_data\workspace-{agent-id}\memory\
```

### 2. 命名

格式：`task-summary_{YYYY-MM-DD}_{HHmm}.md`

示例：
- `task-summary_2026-05-15_0900.md`
- `task-summary_2026-05-15_1430.md`

规则：
- 日期用 **连字符** 分隔（2026-05-15）
- 时间取任务**结束时**的小时+分钟（24小时制，4位）
- 同一天多个任务，时间戳自然区分

### 3. 内容格式

每份日志必须包含以下三个段落：

```markdown
# task-summary_{日期}_{时间}

## Objective
（本次任务的目标是什么？用户要求了什么？）

## Key Reasoning
（关键的推理过程、决策依据、遇到的问题及解决方式）

## Conclusions
（最终结论、产出物、待跟进事项）
```

### 4. 写入时机

**一个任务结束时写一份日志。**

- "任务" = 一次完整的对话/需求，从接收到交付
- 多轮互动属于同一任务，结束时只写一份
- 禁止每个 turn 都写一份（避免碎片化）

### 5. 每日必写

每个 Agent **每个工作日至少有一份日志**，即使当天只有简单任务。
如果当天没有接到任何任务，写一份简要的"待命中"日志：

```markdown
# task-summary_{日期}_{时间}

## Objective
当日待命，无任务分配。

## Key Reasoning
无

## Conclusions
待命中，随时可以接受任务。
```

---

## 🔧 迁移要求

现有散落在 workspace 根目录的 task-summary 文件，逐步迁移到 `memory/` 目录下并统一重命名。
新产生的日志必须严格遵循本规范。

---

## 📌 执行检查

牛牛（主协调者）负责在 heartbeat 检查中抽查各 Agent 日志合规性：
- 是否在 `memory/` 目录下
- 命名是否符合规范
- 内容是否包含三个必要段落
- 是否每日有日志

发现问题及时提醒对应 Agent 修正。
